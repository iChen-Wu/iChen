# 数据与备份说明

## 一、数据在哪

iChen 的所有运行时数据都在**各版本自己的** `data/` 下（路径常量唯一来源：
`shared/common/paths.py`）：

```
data/
├── config/
│   ├── config.yaml            # 中枢配置
│   ├── score_rules.json       # 积分规则
│   ├── class_datacenter.json  # 数据中心白名单（person / points_record / points_edit）
│   └── .env                   # 密钥（不入库、不外传）
├── db/
│   ├── gyun_data.db           # ★ GYun 共享业务库（SQLite）——最重要的文件
│   ├── gyun_data.db-wal       # SQLite WAL（未 checkpoint 的最新写入）
│   ├── gyun_data.db-shm       # SQLite 共享内存索引
│   └── backups/               # 数据库备份目录
├── automation.json            # 自动化配置
└── local_config.json          # 本机设置（无边框开关等）
```

## 二、三版本的数据边界

| 版本 | data/ 内容 | 处置 |
|---|---|---|
| 开发版 `d:\workspace\iChen` | 开发测试数据 | 可随意重置，不承载真实业务 |
| **正式版 `D:\iChen`** | **真实业务库，日常数据全在这** | **最高保护级别** |
| 移动版 `F:\iChen` | 干净空库 | U 盘不可靠，不存放唯一数据 |

- 正式版业务库（2026-10-05 时点）：`gyun_data.db` 约 6.2 MB，约 2798 个实体——
  班级管理 1755（student_ledger 1576 / points_record 76 / person 66 / config 37）、
  WYuan 1035、Qxia 5。数据中心经白名单可见 119 条（66 人 + 53 积分记录），软删除数据不显示。
- `shared/GYun/data/runtime/gyun_data.db` 是 V3 路径迁移前的历史副本（2785 条），
  **新代码不读它**，只作留存。
- 正式版留有空壳样本：`gyun_data.db.empty_20261004`（事故记录，勿删勿混用）。

## 三、红线

1. **任何更新 / 同步 / 部署动作都不得覆盖正式版 `data/`**（更新工具已硬编码保护）。
2. 不要用"拷贝一个空 db 过去"的方式处理报错——中枢在找不到库时会**自动建空库**，
   表面是程序正常启动、实则数据全空。
3. 不要在三个版本之间互相拷贝 `data/`、`shared/GYun/data/`。
4. `.env` 含密钥，不进 git、不发给任何工具 / 文档。
5. U 盘（F:）写入曾出现整文件变 null 字节、目录链断裂，**绝不把唯一数据留在 F 盘**。

## 四、备份操作

### 常规手动备份（更新前必做）

```bat
:: 1. 先完全退出 iChen（托盘退出），保证 WAL 已落盘
:: 2. 复制（日期自行替换）
copy D:\iChen\data\db\gyun_data.db ^
     D:\iChen\data\db\backups\gyun_data_YYYYMMDD.db
:: 3. 核对大小不为 0、与源文件接近
dir D:\iChen\data\db\backups
```

如果中枢正在运行无法退出，连 `-wal`、`-shm` 三个文件一起复制，或用 SQLite 的备份接口，
不要只拷主库（可能缺最新写入）。

### 建议节奏

- 每次正式版更新前：1 份带日期的备份（见《正式版更新指南》）；
- 大批量导入 / 改积分规则前后：各 1 份；
- `backups/` 保留最近若干份，重要节点的备份可另存到其他磁盘。

### 恢复

1. 退出 iChen；
2. 把备份复制回 `data/db/gyun_data.db`（若当时连 WAL 一起备份的，三个文件一起还原）；
3. 重启中枢，打开数据中心 / 积分管理核对条数与近期记录。

## 五、事故记录（教训）

- **2026-10-04 空库事故**：V3 同步时正式版尚无新路径下的业务库，中枢启动自动建空库，
  业务数据看似全部丢失。用开发版留存的数据库恢复后还原。直接后果：
  ① 更新工具改为只同步 `system/`、`main.py`、`README.md`，永久保护 `apps/ shared/ data/ runtime/`；
  ② 本说明固化备份要求。
- **F 盘写入损坏**（FAT32）：整文件 null 化、Scripts/site-packages 目录曾变成文件，
  经 chkdsk 修复。移动版部署规则：D 盘 `pip --target` 暂存 → robocopy 顺序写入 →
  null 字节扫描 + chkdsk + 导入三重校验；禁止在 U 盘上直接跑 pip。
